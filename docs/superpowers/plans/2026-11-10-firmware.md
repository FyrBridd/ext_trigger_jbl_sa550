# Dongle Firmware Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Firmware for the ATtiny412 dongle that keeps a JBL SA550 switched on and on its STB input over RS232, proven against a simulated amp on the Linux box and shipped as ready-to-flash hex files with a written bring-up procedure.

**Architecture:** Plain C in three hardware-free modules (frame protocol, controller state machine, command table) glued by a small `app` loop that talks to a hardware interface (`hal.h`). On the host, the same `app` is linked against a fake hardware layer and a simulated amp, so whole scenarios run under a virtual clock. On the AVR, `hal_avr.c` is the only file touching registers.

**Tech Stack:** C11, avr-gcc and avr-libc (ATtiny412), host gcc, make, Python 3 (two small build-check and decode tools), pytest. Everything runs through `tools/dev`.

**Spec:** `docs/superpowers/specs/2026-11-10-wiim-trigger-jbl-dongle-design.md` (sections 3.2, 7 and 11). Read it before starting.

**Prerequisite:** Task 1 of `2026-11-10-hardware.md` (the dev container and `tools/dev`).

## Global Constraints

- No Arduino framework; no dynamic memory; no floating point.
- Target ATtiny412 at 3.3 V on the internal oscillator: `F_CPU=3333333UL`. Serial is 38,400 baud, 8N1.
- Pins: PA6 USART transmit, PA7 USART receive, PA3 LED (high = on), PA1 debug trace output, PA0 UPDI (never reconfigured).
- Every build variant must fit 4096 bytes of flash and 256 bytes of RAM (ATtiny412 and ATtiny402). The default release variant should also be reported against 2048 bytes (ATtiny202); exceeding that is not a failure.
- The firmware never sends power-off, volume, or processor-mode commands.
- All timings are named constants in `firmware/src/config.h`, overridable with `-D`.
- Compiler flags for both host and AVR: `-std=c11 -Wall -Wextra -Werror`.
- Fuses must leave PA0 as UPDI (`SYSCFG0` bits 3:2 = `01`).
- Commit after each task with the message given. Commit messages end with the line `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.

## Review Focus

Conditions the spec implies that are most likely to bite on the real amp:

1. **Reply data that looks like framing.** A data byte equal to `21` or `0D` inside a frame must not split or end it. Pinned by `test_data_bytes_that_look_like_framing` (Task 1).
2. **Millisecond counter wrap-around.** The 16-bit counter wraps every 65.5 s; the dongle runs for hours. Pinned by `test_wraparound` (Task 3) and `scenario_long_run_crosses_wrap` (Task 4).
3. **Unsolicited frames arriving between a query and its reply.** The amp may announce a front-panel change at any moment. Pinned by `test_unsolicited_frame_while_awaiting` (Task 3).
4. **An amp that is silent, then starts answering** (booting, or "RS232 Stdby" off and switched on by hand). Pinned by `scenario_silent_then_switched_on_by_hand` (Task 4).
5. **Line noise and truncated frames at power-up.** Pinned by `test_garbage_and_truncated_frames` (Task 1) and `scenario_noise_on_the_line` (Task 4).

### Task 1: Test harness and frame protocol

**Files:**
- Create: `firmware/Makefile`, `firmware/src/config.h`, `firmware/src/proto.h`, `firmware/src/proto.c`, `firmware/test/test.h`, `firmware/test/test_proto.c`

**Interfaces:**
- Produces:
  - `uint8_t proto_build(uint8_t *buf, uint8_t cmd, const uint8_t *data, uint8_t len);` writes `21 01 <cmd> <len> <data...> 0D`, returns the frame length (`len + 5`).
  - `typedef struct proto_parser proto_parser_t;` (complete type in the header so it can live on the stack or in static storage).
  - `void proto_parser_init(proto_parser_t *p);`
  - `bool proto_parser_feed(proto_parser_t *p, uint8_t byte, proto_frame_t *out);` returns true exactly when `byte` completes a valid response frame, which is copied to `*out`.
  - `bool proto_parser_busy(const proto_parser_t *p);` true when part-way through a frame.
  - `make -C firmware test` builds and runs every host test binary and fails if any test fails.

Parser rules. A response is `21 <zone> <cmd> <answer> <len> <data × len> 0D`. Bytes before `21` are skipped. The frame's extent is decided by `<len>`, never by searching for `0D`. If the byte after the data is not `0D`, or `<len>` exceeds `PROTO_MAX_DATA`, the frame is dropped and the parser returns to hunting for `21`, starting with the next byte.

### Task 3: Controller state machine

**Files:**
- Create: `firmware/src/ctrl.h`, `firmware/src/ctrl.c`, `firmware/test/test_ctrl.c`
- Modify: `firmware/Makefile`

**Interfaces:**
- Consumes: `proto_frame_t`, `config.h`.
- Produces:
  - `typedef struct ctrl ctrl_t;` (complete type in the header).
  - `void ctrl_init(ctrl_t *c, uint16_t now);`
  - `void ctrl_on_frame(ctrl_t *c, const proto_frame_t *f, uint16_t now);`
  - `ctrl_send_t ctrl_step(ctrl_t *c, uint16_t now);` returns at most one command per call; call it every loop pass.
  - `ctrl_led_t ctrl_led(const ctrl_t *c);`

`now` is a free-running 16-bit millisecond counter. Compare times only as `(int16_t)(now - deadline) >= 0`.

Behaviour rules:

1. **Start.** `ctrl_step` returns `SEND_NONE` until `STARTUP_MS` after `ctrl_init`, then `SEND_POWER_QUERY`.
2. **Awaiting.** After a query, `ctrl_step` returns `SEND_NONE` until the matching reply arrives or `REPLY_TIMEOUT_MS` passes. A reply matches when its `cmd` equals the query's command (`00` for power, `1D` for input). A frame with any other `cmd` does not end the wait.
3. **Power result.** Reply with `answer == 00`, `len >= 1`, `data[0] == 01` means on. Anything else (`data[0] == 00`, a non-zero `answer`, or a timeout) means not on: the next `ctrl_step` returns `SEND_POWER_ON`, and the next power query goes out `WAKE_POLL_MS` after that.
4. **Settle.** When the amp reports on and the previous power result was not on (or there was none), wait `SETTLE_MS` before the input query. When it was already on, send the input query on the next `ctrl_step`.
5. **Input result.** Reply with `answer == 00`, `len >= 1`, `(data[0] & 0x0F) == INPUT_STB` means the input is right: the next cycle (a power query) starts `POLL_MS` later. A good reply with another input: the next `ctrl_step` returns `SEND_SELECT_STB`, and the next cycle starts `WAKE_POLL_MS` after that. A non-zero `answer` or a timeout: send nothing, and start the next cycle `WAKE_POLL_MS` later.
6. **Unsolicited frames.** Every good `cmd 00` or `cmd 1D` frame updates the last power or input result (and so the LED), whether or not it was asked for. While not awaiting that command's reply, a `cmd 00` frame with `data[0] == 00`, or a `cmd 1D` frame whose low nibble is not `INPUT_STB`, also makes the next cycle start on the next `ctrl_step`. If it arrives while awaiting a different command's reply, the current wait finishes first and the cycle carries on from there.
7. **`CFG_INPUT_QUERY == 0`.** Never return `SEND_INPUT_QUERY`. Where rule 4 would send it after a settle, return `SEND_SELECT_STB` once instead; where the amp was already on, send nothing. Treat the input as right afterwards. Rule 6 still applies and leads to another `SEND_SELECT_STB` (after the power query confirms on).
8. **LED.** `LED_FAST` when the most recent power query timed out and no valid frame has arrived since. `LED_SOLID` when the last power result was on and the last input result was right. Otherwise `LED_SLOW`. Before the first result, `LED_SLOW`.

#include "test.h"
#include "proto.h"
#include "ctrl.h"
#include "config.h"

static ctrl_t c; static uint16_t t;
static proto_frame_t fr(uint8_t cmd, uint8_t answer, uint8_t d0) {
  proto_frame_t f = { .zone = 1, .cmd = cmd, .answer = answer, .len = 1, .data = { d0 } }; return f; }
static void rx(uint8_t cmd, uint8_t answer, uint8_t d0) { proto_frame_t f = fr(cmd, answer, d0); ctrl_on_frame(&c, &f, t); }
static ctrl_send_t step(void) { return ctrl_step(&c, t); }
/* advance 1 ms at a time until a command comes out or ms have passed; returns it (or SEND_NONE) */
static ctrl_send_t run(uint16_t ms) { for (uint16_t i = 0; i < ms; i++) { ctrl_send_t s = step(); if (s) return s; t++; } return step(); }
static void start(uint16_t t0) { t = t0; ctrl_init(&c, t); }
/* bring the controller to steady state: on, STB, next poll pending */
static void steady(uint16_t t0) { start(t0); CHECK_EQ(run(STARTUP_MS), SEND_POWER_QUERY); rx(0x00, 0, 1);
  CHECK_EQ(run(SETTLE_MS), SEND_INPUT_QUERY); rx(0x1D, 0, 0x15); CHECK_EQ(ctrl_led(&c), LED_SOLID); }

  - `python tools/decode_eeprom.py <file>` prints the log. It accepts a raw binary dump, or an Intel HEX file in which the EEPROM is either at address 0 or at `0x810000` (Microchip's convention). Function `decode(data: bytes) -> dict`.
  - The test binary `build/host/test_dbglog` writes `build/host/dbglog_golden.bin` (the fake EEPROM after a fixed sequence), which the Python test decodes.

EEPROM layout (104 bytes used of 128):

| Offset | Content |
|---|---|
| 0 | magic `D5` |
| 1 | layout version `01` |
| 2 | boot count, stops at 255 |
| 3 | unused |
| 4 + 20·k | bucket k, for k = 0 power query, 1 power on, 2 input query, 3 select STB, 4 unsolicited |

Each 20-byte bucket: byte 0 = timeouts (stops at 255); byte 1 = number of records (0–3); then three 6-byte records `cmd, answer, len, data0, data1, data2`.

Rules:
- `dbglog_init`: if the magic or version is wrong, write the header and zero every bucket's first two bytes; then add one to the boot count.
- `dbglog_sent(what)`: if the previous command sent got no frame at all before this call, add one to that command's timeout count. Remember `what` as the current command.
- `dbglog_frame(f)`: the first frame after a `dbglog_sent` belongs to that command's bucket; later frames before the next send, and frames before any send, belong to the unsolicited bucket. Store the frame only if the bucket has fewer than 3 records and no identical record already.

Hardware layer:
- **Clock:** leave the reset default (20 MHz oscillator, divide by 6).
- **USART0:** PA6 output driven high before enabling; PA7 input. `BAUD = 4 × F_CPU / 38400` (347), corrected with the factory value: `baud += (int32_t)baud × (int8_t)SIGROW.OSC20ERR3V / 1024`. 8N1. Receive by interrupt into a 16-byte ring buffer; transmit by polling `DREIF`.
- **Tick:** TCB0 periodic interrupt every 1 ms (`CCMP = F_CPU / 1000 − 1`), incrementing a 16-bit counter; `hal_millis` reads it with interrupts briefly off.
- **LED:** PA3.
- **Watchdog:** enabled by fuse; `hal_wdt_kick` is `wdt_reset()`.
- **Debug trace (`CFG_DEBUG`):** PA1 idles high; `hal_dbg_putc` bit-bangs one 38,400 baud 8N1 byte with interrupts off for that byte (260 µs; the USART's two-byte receive buffer covers it).
- **EEPROM (`CFG_DEBUG`):** `eeprom_read_byte` / `eeprom_update_byte`.
- `main` calls `hal_init()`, enables interrupts, calls `app_init()`, then loops on `app_step()`.

|---|---|---|---|
| 0 | WDTCFG | `0x0A` | watchdog always on, 4 s |

| 2 | OSCCFG | `0x02` | 20 MHz oscillator (default) |
| 4 | TCD0CFG | `0x00` | default |
| 5 | SYSCFG0 | `0xF6` | default: PA0 stays UPDI, EEPROM erased with chip erase |
| 6 | SYSCFG1 | `0x07` | default start-up time 64 ms |
| 7 | APPEND | `0x00` | default |
| 8 | BOOTEND | `0x00` | default |
