# Dongle Hardware (tooling, schematic, board, fabrication files) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a checked KiCad 10 project and JLCPCB fabrication files for the WiiM-trigger-to-RS232 dongle board, entirely from the headless box.

**Architecture:** One Python file (`circuit.py`) is the single source of truth for parts and nets. Scripts generate the schematic (kicad-sch-api) and the board (KiCad's `pcbnew` Python module) from it; nobody hand-writes KiCad file syntax. Every stage is gated by `kicad-cli` checks run through pytest. All tools run in one Docker container.

**Tech Stack:** Docker, `kicad/kicad:10.0` image (KiCad 10.0.8, Python 3.13, `pcbnew`), kicad-sch-api 0.5.5, pytest, `kicad-cli`.

**Spec:** `docs/superpowers/specs/2026-11-10-wiim-trigger-jbl-dongle-design.md` (sections 5, 6, 9 and 10 are the ones this plan implements). Read it before starting.

**Companion plans:** `2026-11-10-firmware.md` (needs only Task 1 of this plan). The enclosure gets its own plan after this one finishes, because it needs the board's 3D model and the owner's cable measurements.

## Global Constraints

- All commands run through `tools/dev <command>` (Task 1). The box has no passwordless sudo; never use sudo.
- KiCad project files under `hardware/dongle/` are generated. Never edit them by hand; change `circuit.py`, `layout.py` or a generator and regenerate.
- Board: 2 layers, 1.6 mm, every assembled part on the top side, ground pour on the bottom.
- Outline: target 12 × 38 mm; hard limits width ≤ 14 mm, length ≤ 45 mm, each side ≥ 10 mm.
- Assembled parts ≥ 1.0 mm from the board edge. Passives are 0603, except the two 10 µF capacitors (0805). Nothing smaller.
- Parts and LCSC numbers exactly as the spec's section 6 table (R1 is 100 Ω, C22775).
- U2 pin 6 (PA0/UPDI) connects only to the programming footprint pad 4 and one test pad.
- Programming footprint pads 1, 5 and 6 are unconnected.
- Every review document is a PDF or Markdown file in the repository; the owner must be able to review the whole design without opening KiCad.
- Done means: ERC zero errors; exported netlist equals `circuit.py`; DRC zero errors, zero unconnected items, schematic parity clean; stock gate passes.
- Commit after each task with the message given. Commit messages end with the line `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.

## Review Focus

Failure modes the spec implies that are most likely to cost a board respin:

1. A symbol pin number that does not match the real part's pin (HT7533 pin order, SP3232 charge-pump pins, diode polarity). Pinned by Task 5 (independent datasheet review) and `test_pin_functions` in Task 2.
2. Schematic and board silently disagreeing. Pinned by the netlist-equality test (Task 4) and DRC schematic parity (Task 7).
3. Programming footprint pads in the wrong physical order for the TC2030-MCP-NL cable. Pinned by Task 3's datasheet check and `test_tc2030_pad_positions`.
4. A part placed by JLCPCB rotated 180° (SOT-89, SOIC, TSSOP, diodes). Pinned by `test_cpl_rotations` in Task 8 and the owner's check of JLCPCB's placement preview (Task 10).
5. Wire pads or strain-relief holes too close to the edge or to each other to survive soldering. Pinned by `test_wire_pad_geometry` in Task 3 and `test_edge_clearance` in Task 6.

def test_wire_pad_geometry():
    for n, name in ((2, "WirePads_1x02_Strain"), (3, "WirePads_1x03_Strain")):

        plated = sorted((p for p in fp.Pads() if p.GetAttribute() == pcbnew.PAD_ATTRIB_PTH), key=lambda p: p.GetNumber())

### Task 4: Schematic generator with ERC and netlist checks

**Files:**
- Create: `hardware/design/gen_sch.py`, `hardware/design/kicad.py`, `hardware/tests/test_schematic.py`
- Generated: `hardware/dongle/dongle.kicad_sch`, `hardware/dongle/dongle.kicad_pro`, `hardware/dongle/fp-lib-table`, `hardware/fab/schematic.pdf`

**Interfaces:**
- Consumes: `circuit.PARTS`, `circuit.NETS`, `circuit.NO_CONNECT`.
- Produces:
  - `gen_sch.main()` writes the project files; run as `python -m hardware.design.gen_sch`.
  - `gen_sch.symbol_uuid(ref: str) -> str`, a deterministic `uuid.uuid5` per reference. Task 6 uses it to link footprints to symbols.
  - `kicad.erc(sch_path) -> list[dict]` (violations with `type`, `severity`, `description`), `kicad.export_netlist(sch_path) -> dict[str, set[tuple[str, str]]]` (net name to pins), `kicad.export_pdf(sch_path, out_path)`.

What the spike on this box already established (kicad-sch-api 0.5.5 with KiCad 10.0.8):
- `sch = kicad_sch_api.create_schematic("dongle")`; `sch.components.add(lib_id, reference=, value=, position=(x, y), footprint=, component_uuid=, **properties)`; extra keyword properties (for example `LCSC="C21190"`) become symbol fields.
- `sch.add_label("NET", pin=("R1", "1"))` attaches a label directly to a pin, and KiCad's ERC treats the pin as connected. Use this for every connection; draw no wires.
- `sch.no_connects.add(...)` places no-connect flags; `sch.get_component_pin_position(ref, pin)` gives a pin's position.
- `sch.save(path)` output loads in `kicad-cli` without errors.
